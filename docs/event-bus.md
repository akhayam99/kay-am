# Custom window events

> **Read this when** dispatching or listening for custom window events in apps/desktop. **Not for** Tauri inter-window communication or other message protocols (`docs/worktree-bridge.md`).

Every event on this page is a browser CustomEvent sent via `window.dispatchEvent()` and received via `window.addEventListener()`. Payloads are the `detail` field.

## Adding an event

Event names follow the pattern `goodboy:verb-noun` (e.g., `goodboy:open-plan-studio`, `goodboy:reveal-chat`). Every event must be dispatched and listened in the same pull request; a listener without a dispatch is unreachable code. Payloads should stay minimal: pass only the ids and enums needed to route or initialize a feature, never entire objects. If an event grows past three fields, reconsider whether routing logic belongs in a store method instead.
